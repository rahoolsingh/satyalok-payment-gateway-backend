# Deploying recurring donations

Everything here assumes the existing setup: the backend deploys with GitHub
Actions on a push to `main` (SSH + `docker compose up -d --build`), and the
frontend deploys on Vercel from `vercel.json`.

There is **no deploy path that skips `main`** for the backend today, so treat the
merge as the release itself.

---

## 0. Why it is not deployed yet

The backend needs credentials that do not exist in the repo:

| Setting | Where it comes from |
|---|---|
| `PHONEPE_AUTOPAY_*` | PhonePe dashboard, after **UPI AutoPay** is enabled for the merchant |
| `PLEDGE_ENCRYPTION_KEY`, `PLEDGE_HASH_PEPPER`, `PLEDGE_PORTAL_SECRET` | generated by you, `openssl rand -base64 48` |
| `PHONEPE_AUTOPAY_WEBHOOK_USERNAME/PASSWORD` | set by you on the PhonePe dashboard |

Until those are on the server, `POST /pledge` answers **503
`AUTOPAY_NOT_CONFIGURED`** by design. The page, the validation and the donor
portal all work; the gateway step does not. That is the honest state of a deploy
without credentials.

---

## 1. Frontend — Vercel

1. Import `satyalok-payment-gateway-frontend`, branch
   `feat/recurring-donations`.
2. Framework preset: **Vite**. Build `npm run build`, output `dist`.
3. Environment variable, **required at build time**:
   `VITE_BACKEND_URL = https://<your-api-host>` (no trailing slash).
4. Deploy. Preview deployments are free and do not touch production — use one to
   walk through `/pledge` before promoting.

`vercel.json` already rewrites every path to `index.html`, so `/pledge`,
`/pledge/status` and `/pledge/manage/<token>` resolve on a hard refresh.

---

## 2. Backend — existing CI

1. Put the variables from `sampl.env` into the server's
   `/root/Satyalok_PG_Backend/.env`. Nothing else reads them.
2. Merge `feat/recurring-donations` into `main`.
3. The workflow SSHes in, `git pull`s, rebuilds and restarts. Watch it under
   **Actions → Deploy backend on server**.
4. Confirm it came up:

```bash
curl -s https://<your-api-host>/ | jq .alive            # true
curl -s https://<your-api-host>/pledge/plans | jq '.plans | length'   # 3
```

Three plans means the new router is live. A 404 means the container is still
running the old image.

---

## 3. PhonePe dashboard

1. Enable **UPI AutoPay** (a separate product flag from standard checkout).
2. Webhook URL: `https://<your-api-host>/webhook/phonepe/autopay`
3. Copy the dashboard webhook username/password into
   `PHONEPE_AUTOPAY_WEBHOOK_*` and restart the container.
4. Keep `PHONEPE_AUTOPAY_ENV=SANDBOX` until a test pledge settles end to end.

---

## 4. First live check, in order

1. `GET /pledge/plans` returns 3 tiers.
2. `/pledge` → submit ₹100 with a real UPI ID you control.
3. Approve the mandate in the UPI app.
4. Within ~10s `/pledge/status?ref=...` flips to **active** and the receipt email
   arrives with the 80G certificate.
5. Open the manage link: **Skip this month** moves the next debit, **Cancel**
   stops it and the pledge shows `cancelled`.
6. Cancel again from the app's mandate list and confirm the pledge mirrors it.

If step 3 succeeds but step 4 does not, the webhook is not reaching the server —
check the URL and the two webhook credentials before anything else.

---

## 5. Rollback

The schema changes are additive (new collections plus new optional fields on
`Donation`), so rolling back is safe and one step:

```bash
git revert <merge-commit> && git push    # redeploys the previous image
```

Existing pledges keep working: the debit engine and the webhook router simply
stop being reachable, and no money moves without them.

---

## 6. Image build

`Dockerfile` now runs `npm ci --omit=dev`. Before this change `npm install`
pulled `mongodb-memory-server`, which downloads a ~140MB `mongod` binary during
the image build. Production needs none of it.
